## Authorization taxonomy

- **Invocation-local human consent:** the guided/manual command intent and exact eligibility/source verifier; never persisted.
- **Handoff reservation authority:** the immutable protected reservation plus active-source binding and reservation event; migrated here.
- **Handoff-specific durable authorization:** no separate production object exists. The initial projection's `NOT_AUTHORIZED / NOT_COMMITTED / NOT_STARTED` values are required empty-state facts, not a YES capability.
- **Resume authorization:** project `authorizations`, created only after a separate resume prompt and final U*; explicitly not migrated.
- **Admission:** project `admissions`; explicitly not migrated.
- **Dispatch:** project `dispatch_attempts`; explicitly not migrated.

Secure handoff therefore never trusts a project `authorizations`, `admissions`, or `dispatch_attempts` row. `prepareResumeConfirmation()` and `resume()` return `SECURE_RESUME_AUTHORITY_UNAVAILABLE`; the real target remains paused at `RESUME_READY`. Recovery similarly returns `SECURE_RECOVERY_AUTHORITY_UNAVAILABLE`.

## Protected architecture

Protected schema is `aiopago.operation-authority/1.2.0`; fixed protocol is `aiopago.operation-authority-protocol/3`.

New canonical tables:

- `handoff_reservations(handoff_id PK, source_session_id, task_id, task_plan_revision, task_plan_digest, latch_generation, latch_reason, runner_instance_id, recovery_of_handoff_id, checkpoint_id, resume_manifest_id, reservation_digest, reservation_event_id UNIQUE, projection_json, created_at)`;
- `active_sources(source_session_id PK, handoff_id UNIQUE FK)`;
- `handoff_reservation_events(sequence PK, event_id UNIQUE, request_id UNIQUE, handoff_id UNIQUE, task_id, source_session_id, event_type, latch_generation, latch_reason, occurred_at)`.

Fixed semantic operations added: `HANDOFF_RESERVE`, `HANDOFF_GET`, `HANDOFF_LATEST_TASK`, and `ACTIVE_SOURCE_GET`. No arbitrary SQL, GuardianStorage method, Runner method, eval, module load, generic release, resume, recovery, admission, dispatch, or public listener was added. Test crash seams remain accepted only for scoped test service identities.

Secure and portable authority never fall back into one another. Protected service/DB/schema/protocol/identity/channel failure cannot select project handoff state. Project projection happens only after canonical commit; projection failure cannot roll back or redefine canonical success. A later exact secure read/retry still sees the protected reservation.

## Exact reservation identity and conflicts

The recovered stable identity is:

`handoff_id`, `source_session_id`, `source_session_file`, `task_id`, `task_plan_revision`, `task_plan_digest`, `requirements_version`, `current_item`, `next_item`, `next_step`, `latch_generation`, `runner_instance_id`, `session_binding_id`, `parent_session_id`, `parent_session_file`, `parent_checkpoint_id`, `recovery_of_handoff_id`, `checkpoint_id`, `resume_manifest_id`, `model_policy`, and `reasoning_policy`.

The protected request digest additionally binds the exact latch state/generation/reason, complete immutable initial projection/reserved plan snapshot, and expected latest protected reservation. Source lifecycle epoch is intentionally not invented as durable state: trusted P2 verifies it synchronously immediately before final reservation; durable lifecycle authority remains later.

Exact request replay returns the recorded result. Same request or handoff ID with changed payload conflicts. A source already bound to any different task/session/provenance conflicts with `HANDOFF_ACTIVE_SOURCE_CONFLICT`. No last-writer-wins exists.

Until durable lifecycle transfer is migrated, a different secure reservation for a task that already has a protected reservation fails closed with `HANDOFF_TASK_RESERVATION_CONFLICT`. This deliberately disables later secure lifecycle/recovery forks rather than trusting project terminal/recovery state. It does not claim lifecycle migration.

## Security properties

- takeover first → reservation denied; zero protected reservation, active source, event, or request;
- reservation first → exact reservation remains; later takeover blocks replacement/progress on fresh protected latch reread;
- concurrent takeover/reservation → SQLite chooses one valid serialization;
- forged project clear/takeover → no canonical effect;
- forged project handoff/active source/event/high state → no canonical effect;
- deleted or changed project projection → protected reservation and active source remain exact; a conflicting secure request still rejects;
- forced protected event insertion failure → complete transaction rollback;
- crash after handoff and active-source inserts but before COMMIT → no partial state after restart;
- crash/restart after COMMIT → canonical reservation survives without projection;
- project resume authorization/admission/dispatch forgery → no secure automatic progress.

The semantic integration harness uses genuine Pi 0.83.0 and the production HandoffService/SafePoint/Runner path with `ProtectedSqliteOperationAuthority` selected directly against a scoped test store. It creates one canonical reservation, writes only a compatibility projection afterward, creates the replacement paused, reaches `RESUME_READY`, and records zero resume authorization/admission/dispatch. This integration harness is not the OS-identity oracle. Separately, the elevated physical oracle runs the same protected reservation implementation inside real service-SID P2 over the private P1S channel and proves P0/cross-service denial, restart, crash and protocol properties. The activated-source P0 can still reconstruct portable authority and invoke reachable commands, but it has no service SID/private channel/protected DB access and creates zero protected reservation or active source.

## Remaining boundary

Plan revision/digest, Runner-local source lifecycle, replacement bindings, handoff lifecycle transitions, resume authorization/admission/dispatch, recovery, and artifact bytes remain separate authority domains. Reservation binds their current IDs/provenance but does not authenticate later portable mutation. Secure status selects the protected reservation and never merges a later-looking project forgery as canonical.

The next recommended domain is **lifecycle/session binding authority**. It is exposed by the deliberate fail-closed rule that prevents a second task reservation until a protected lifecycle owner can be proved/transferred. Resume authorization/admission/dispatch remains separate and must not be pulled forward merely to release this reservation.
